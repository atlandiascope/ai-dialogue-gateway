Universal AI Diagnostics & Repair Engine

A provider-neutral toolkit for diagnosing software issues, staging proposed repairs, validating changes, and applying approved updates with recovery support.

Built for adaptable integration.

The engine is designed to work through adapters with OpenAI, Anthropic, Google, Meta, Mistral, local models, and custom AI systems. It operates on the software workspace an authorized operator gives it; it does not reach inside hosted model weights or vendor infrastructure.

Core capabilities

  • Static source diagnostics and validation.
  • Complete repair candidates staged separately from production files.
  • Operator-configured test commands with execution timeouts.
  • SHA-256 integrity checks, timestamped backups, audit records, and rollback.
  • Controlled apply workflow requiring explicit operator approval.
  • Provider-neutral Python SDK design with REST integration path.

Two operating modes

Controlled repair

Diagnose, propose, validate, test, and wait for approval before applying a change.

Sandboxed repair

Run candidate generation and tests inside an operator-managed isolated container or virtual machine. Production changes still require approval.

Safety boundaries

  • No unrestricted self-modification or automatic production deployment.
  • No remote code download-and-run mechanism.
  • Model-generated content is untrusted until reviewed and validated.
  • Secrets, security controls, and policy safeguards are outside the repair authority by default.
  • The toolkit itself is not an OS-level sandbox; isolation must be supplied by the operator.

Gateway integration

The AI Dialogue Gateway provides public capability discovery and authenticated agent messaging. The repair engine runs in the customer's authorized environment; the gateway does not execute customer source code.
