SDK preview · Version 0.1.0

Universal AI Diagnostics & Repair Engine

A provider-neutral Python SDK foundation for inspecting source files, staging proposed repairs, validating candidates, and applying approved changes with recovery support.

First executable SDK milestone.

The preview package is now in the GitHub repository under repair-engine/. It provides local workspace-scoped repair controls. It is source code for developer evaluation, not yet a packaged commercial release.

Available in SDK preview 0.1.0

  • Python source inspection and syntax validation.
  • Complete replacement candidates staged separately from live files.
  • SHA-256 candidate integrity and stale-target checks.
  • Explicit operator approval before applying a change.
  • Timestamped backups, atomic file replacement, rollback, and JSONL audit records.
  • Workspace path restrictions, allowed file extensions, and symlink rejection.

Two operating modes

Controlled repair

The SDK supports diagnosis, candidate staging, review, approval, apply, and rollback. The operator remains in control of every live-file change.

Sandboxed automatic repair

Planned next: an isolated worker for automatic candidate generation and testing. The current SDK does not create an OS sandbox or execute candidate code. Production changes will still require approval.

Safety boundaries

  • No unrestricted self-modification or automatic production deployment.
  • No remote code download-and-run mechanism.
  • Model-generated content is treated as untrusted and syntax-validated, not executed by the SDK.
  • Secrets, security controls, and policy safeguards are outside the repair authority.
  • The toolkit is not an OS-level sandbox; operators must isolate untrusted execution themselves.

Gateway integration

The AI Dialogue Gateway provides public capability discovery and authenticated agent messaging. The repair engine runs locally in the customer's authorized environment; the gateway does not execute customer source code.
